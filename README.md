# reading-notes

読んだ本の「疑問」と「学び」を残す個人用リポジトリ。

要約は書かない。**わからなかったこと・迷ったこと**を起点に残す。

## 方針

- 1冊 = 1ファイル。ジャンルごとにディレクトリを分ける
- 1エントリ = 1つの疑問（または1つの学び）
- 綺麗に書こうとしない。3行の殴り書きで十分
- その場で解決しなくてよい。腑に落ちないものは `status: 未回収` のまま置く

## 書き方

必須は3つだけ。あとは自由記述。

| 項目 | 目的 |
| --- | --- |
| 一行要約 | 後で一覧を眺めたとき、何の話か思い出せるように |
| 日付 | 疑問が生まれた日。回収までの落差が残る |
| `status: 未回収` | 腑に落ちていないものだけ付ける |

解決したら `status` を消すか、`解決 (YYYY-MM-DD 回収)` に書き換える。

### チェックリスト（強制ではない）

- AIに投げる前に、自分の仮説を書いたか
- AIの回答をコピペせず、自分の言葉に直したか
- 仮説とのズレ（誤解していた点）を書いたか
- 自分のコードのどこに効くか、接続を書いたか

## 使い方

新しい本を読み始めるとき:

```sh
cp template.md engineering/readable-code.md
```

冒頭の書籍情報を埋めて、読みながらエントリを追記していく。

まだ腑に落ちていないことの一覧:

```sh
grep -rn "未回収" .
```

## 構成

```
.
├── README.md
├── template.md
├── engineering/   技術書
├── business/      簿記・経営など
├── marketing/     マーケティング
└── lifestyle/     暮らし・習慣・自己啓発
```
