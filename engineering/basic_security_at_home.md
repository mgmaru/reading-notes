### メモ
1. IPアドレス
- IPアドレス：コンピュータの場所を特定する
- ポート番号：プログラムを特定する
2. ウェルノウンポート
- 20：FTP（データ）
  - FTP：ファイル送受信するための通信プロトコル
- 21：FTP（制御）
- 22：SSH
- 23：Telnet
  - 遠隔地のサーバーやルーターを操作するための通信プロトコル
- 25：SMTP
  - 電子メールを送信・転送するための通信プロトコル
- 80：HTTP
- 110：POP3
  - メールサーバから自分の端末へ電子メールをダウンロードして受信するための通信プロトコル
- 443：HTTPS
- 587：Submission（メール転送）
3. ポート番号の確認
- `netstat -n`コマンド
4. パケット交換
- **回線交換**：通信する端末同士を1対1の回線で繋ぐ。
  - デメリット：１つの通信で１本の回線を占有してしまう。
- **パケット交換**：１本の回線の中に異なる利用者のパケットを混在させながら伝送できる。
  - パケットにアドレスが付いているので、正しい相手に届けることができる。
  - デメリット：回線が混み合ってくると、届くまでの時間が長くなったり、届く前に失われたりする。
5. TCPとUDPの違い
- 前提：IPには「順序」という概念がない。-> **上位層であるTCPでパケットの順序を並び替える。**
- TCPとは
  - **パケットの順序を並び替える**
  - **届いていないデータの再送を要求する**
    - TCPがあるので、開発者はデータが壊れていないかなどを意識する必要がない。
  - デメリット：遅延が発生するので、音声や映像のリアルタイム
6. TCP
- 特徴：送信前にコネクションを確立。相手ごとに接続を管理。
- メリット：再送、到着順序などの制御。信頼性が高い。
- デメリット：ヘッダーのサイズが大きい。負荷が大きい。
7. UDP
- 特徴：コネクションの確立なし。即座にデータを送信。
- メリット：ヘッダーサイズが小さい。負荷が小さい。
- デメリット：パケットロス時にも再送なし。信頼性が低い。
8. MACアドレス
- LANごとに１つ。
  - 有線LANと無線LAN両方を内蔵したコンピュータであれば、それぞれに固有のMACアドレスが付与。
- 48ビットの整数値
  - 前半24ビット：メーカーの識別番号
  - 後半24ビット：各装置に重複しないようにメーカーが割り当てた番号
- 同じPCであってもMACアドレスが変わる場合がある。
  - 仮想デスクトップなど
9. hostsファイル
- **hostsファイル：IPアドレスとホスト名を対応づけて、相互に解決する（名前解決）仕組みの１つ。**
  - Linux：`/etc/hosts`
  - Windows：`system32¥drivers¥etc`
10. DNSとは
- hostsファイルのデメリット
  - 登録するIPアドレスの数が増えると、管理が非効率になる。
  - 複数のPCで設定を共有できない。
  - そこでこれらの問題を解決するために出てきたのがDNS。
- **DNS（Domain Name System）：対応表をサーバーで一元管理して、名前解決する場合に問い合わせる仕組み。**
11. **ドメインツリー**（超重要）
- `www.shoeisha.co.jp`：翔泳社のドメイン
  - トップレベルドメイン：`jp`
  - 第2レベルドメイン：`co`
  - 第3レベルドメイン：`shoeisha`
  - 第4レベルドメイン：`www`
    - トップレベルから第4ドメインまで -> ホスト名
- **個々のDNSサーバは自身が管理するドメイン内の情報とサブドメインのDNSサーバしか知らない。**
  - **上位ドメインはサブドメインのDNSサーバ情報のみを知り、それ以下ドメイン情報は知らない。**
- DNSサーバーをリレー形式で繋いで、IPアドレスを特定する。
12. Webサイトを閲覧する仕組み
  1. PCで`http://www.seshop.com/help/`をURL欄などに入力する。
  2. ブラウザが、URLをプロトコル（`http`）、ホスト名（`www.seshop.com`）、リソース名（`/help/`）に分解する。
  3. DNSにホスト名のIPアドレスを問い合わせる。
  4. DNSからIPアドレスがくる
  5. Webサーバーへリクエスト`GET /help/ HTTP/1.1`を送る。
  6. Webサーバーから指定したリソース（ファイル）をブラウザに送信する。
  7. ブラウザは受け取ったファイルを解釈して表示する。
13. リクエストの送受信
- Webサーバーは利用者を区別しない。
  - １つのWebページはHTMLファイルや画像など複数の要素で構成されている。
  - **各要素へのリクエストは別々にWebサーバーに送信される（1ページにつき1回のリクエストではなく、要素ごとにリクエストを送信する）。**
  - 1回ずつのリクエストが独立して送受信されるため、特定の人が何回アクセスしたかは特定できない。
14. Cookie
- **Cookie：セッションIDをWebサーバへ送ることで、利用者の識別を行うことができる。**
  - 利用者の識別を行うために開発された。
15. ファイアウォール
- 自分の端末で80番ポートにファイアウォールを設定すると、外部との通信を遮断することができる。
  - 自分 -> 遮断 × -> 外部サーバー
  - 自分 <- 遮断 × <- 外部サーバー

### メモ
1. 不正アクセス
- 不正アクセスは**「内部犯行」**と**「外部犯行」**の２つに分けて考えることができる。
  - 2015年ごろは内部犯行の方が圧倒的に多い。
- 外部から攻撃される場合、攻撃しやすいサーバーがターゲットになる。
2. セキュリティホール
- **セキュリティホール：本来できないはずの操作ができてしまったり、見えるべきではない情報が第三者に見えてしまったりするようなバグや不具合。**
- 原因：開発者の知識が不足していたり、セキュリティの意識が低かったりした場合に多い。
3. 盗聴
- **盗聴：伝送中のデータを何らかの手段で他の人が見てしまうこと。**
4. 改ざん
- **改ざん：伝送中のデータを書き換えられてしまうこと。**
  - 例：購入した商品数を書き換えられる。
5. なりすまし
- **なりすまし：他人のふりをして活動すること。**
  - 例：勝手に商品を購入されてしまう。
    - 購入していない商品を証明することが大変。
6. PCの乗っ取りと遠隔操作
- 遠隔操作型マルウェア：マルウェアに感染したPCを遠隔操作することにより、掲示板などに犯行予告を投稿した。
  - 原因：**メールなどでクリックを誘導する。**
7. 標的型攻撃
- **標的型攻撃：特定の組織でよくあると思われるやり取りを模擬したウイルスメールを開封させる。**
  - これは実務でも訓練があった。
8. ソーシャルエンジニアリング
- **ソーシャルエンジニアリング：コンピュータやネットワークの技術は使わずに、侵入に必要なIDやパスワードを物理的な手段で獲得する行為。**
  - 例1：清掃員になりすまして書類を盗み出す。
  - 例2：パスワードを入力しているところを覗き見する。
9. フィッシング詐欺
- **フィッシング詐欺：本物のWebサイトを偽った偽のWebサイトを用意し、メールなどでそのURLに誘導し、IDやパスワードを入力させ、IDやパスワードを盗み出す手口。**
  - 短縮URL

### メモ
1. 電波の不正利用
- PCでファイルの共有設定をONにしていると、プライベートな文書や写真が丸見えになる。
2. アクセスポイント
- アクセスポイントのパスワード設定が初期値になっていることが多い。
  - ID、パスワード：`root`、`admin`など
- アクセスポイントの管理者になると勝手にログを変更されたり、設定を変更されたりする。
3. 不正アクセス対策
  1. 最新版へのアップデートを忘れない。
  2. ファイアウォールの設置
  - ファイアウォール：インターネットと社内ネットワーkの境界に設置して、社内ネットワークの門番を担うネットワーク機器。
  - ファイアウォールの機能
    1. **パケットフィルタリング：IPパケットのヘッダーに含まれる宛先や送信元のIPアドレスやポート番号をチェックして通信を制御する機能。**
    - インターネット上の特定のサーバーとだけ通信する場合は、**社内から宛先が特定のサーバーの通信だけを許可**する。（外向きの通信制御）
    - インターネットからは**送信元が特定の通信のみを許可**する。（内向きの通信制御）
    2. **ステートフルインスペクション：通信プロトコルの仕組みを利用して、ありえない応答を拒否する機能。**
    - 例：TCPは受信側が送信元に正常にパケットが届いたことを伝えるためにACKというフラグをオンにしたパケットを返す。
      - もし、通信を許可した相手からのACKがあれば転送を許可。
      - 通信相手以外から突然ACKが届くことはないので、このような通信をブロックする。
      - **IPスプーフィングなどの偽装した通信を遮断する。**
    3. アプリケーション制御：接続するアプリケーションを判別して遮断する。
4. ファイアウォールでできないこと
- 電子メールの内容は理解できない。
  - 電子メールの疑わしい添付ファイルをスキャンおよび削除するためには、ウィルス対策プログラムを使用する必要がある。
5. ファイアウォールの設定で大切なこと
- OSとルータのファイアウォールの設定をしておく。
6. IPスプーフィング対策
- **IPスプーフィング：IPヘッダーに含まれる送信元アドレスを偽装する攻撃。**
  - 企業によっては「特定のIPアドレスからのみの接続可能」とするが、送信元IPを偽装することでこれを掻い潜ろうとしてくる。
- **ポートスキャンやDNS攻撃などと併用**される。
- 対策：ファイアウォール
  - **外部から内部向けのパケットで設定されている送信元アドレスに、内部のIPアドレスが設定されている場合は、送信元IPアドレスが詐称されていると判断**することができる。
7. hostsファイルをウィルスによって書き換えられると、偽サイトに飛ばされることがある。
- 正しいサイト：http://www.aaa.co.jp（10.222.111.24）
- 偽サイト：http://www.bbb.co.jp（10.222.111.21） ->悪意あるサイト
- hostsファイルをウィルスは以下のように書き換える。
```hosts
10.222.111.21（偽サイトのIP） www.aaa.co.jp（正しいサイトのホスト名）
```
- ユーザは正しいサイト（www.aaa.co.jp）にアクセスしていると思っているが、実際には、偽サイト（www.bbb.co.jp）に飛ばされている。

### わかったこと
1. IPスプーフィングだけではなく、**ARPスプーフィング**という攻撃もある。
2. ファイアウォールのパケットフィルタリング機能は、IPアドレスなどを知らなくても、通信の向きで通信を制御できる。
3. TLSは盗聴などを防ぐ暗号化に使用される。
- ただし、TCPの3ハンドシェイクで接続が確立した後に、TLSハンドシェイクが実行される。
- TLSハンドシェイクが成功すると、HTTP通信が開始される。
- TLSハンドシェイクが失敗すると、TLSを中止して、TCP接続を終了する。
### 思ったこと
1. 3wayハンドシェイクなどの段階で、通信を確立する前に怪しいクライアントとの通信を確立しないような仕組みが必要だと思った。ファイアウォールといったようなネットワークの境界で何か仕組みが必要であると感じた。
- じゃないと、一旦接続を確立してしまうと、それだけで防御側のコストが嵩むような気がした。
2. 「上位の層が守ってくれるから大丈夫」といった設計は良くないと思った。
- 絶対にどこかカバーできていない部分が発生して、セキュリティホールが発生すると思った。
