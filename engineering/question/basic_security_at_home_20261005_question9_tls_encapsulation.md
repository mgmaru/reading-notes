# 『おうちで学べるセキュリティの基本』2026-10-5 疑問9の追加質問：TLSとパケットのカプセル化

## 追加質問

> TLSで暗号化されている場合に、通信先のIPアドレスやポート番号は読めるとのことですが、どこからどこまでが暗号化されているのかを教えてください。これはIP/TCPモデルの中でのアプリケーション層が暗号化されているんですか？おそらくパケットはカプセル化、非カプセル化されると思うのですが、どこでどこまで暗号化されるのか図などを使用して説明してください。

## 回答

**通常の「アプリケーション → TLS → TCP → IP」という通信では、TLSが保護するのはアプリケーションから渡されたデータです。TCPのポート番号やIPアドレスは、その暗号化済みデータを運ぶために後から付けるヘッダーにあるので、途中のルーターやファイアウォールにも見えます。** ただし、TCPのデータ部分がすべて暗号文というわけではありません。TLSレコード自身の外側のヘッダーや、接続開始時の一部のTLSメッセージは平文です。以下は**TCP上のTLS 1.3**を例にします（[RFC 8446、1節・5節](https://www.rfc-editor.org/rfc/rfc8446.html#section-5)、[RFC 9293、2.2節・3.1節](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.1)）。

### TCP/IPの階層ではどこにある？

```text
アプリケーション層  メール本文・添付ファイルを運ぶSMTPなど
                    ↓ 平文のアプリケーションデータを渡す
                  TLS：データを暗号化して「TLSレコード」にする
                    ↓ 暗号化されたレコードを渡す
トランスポート層    TCP：送信元／宛先ポートを付けて運ぶ
                    ↓
インターネット層    IP：送信元／宛先IPアドレスを付けて運ぶ
                    ↓
リンク層            EthernetやWi-Fi：次の機器へフレームを運ぶ
```

4階層のTCP/IPモデルでは、TLSは通常**アプリケーション層側でTCPの上**に置いて説明します。SMTPやHTTPなどのアプリケーションプロトコルとTCPの間に働く、と考えると正確です。「アプリケーション層を丸ごと暗号化する」という意味ではなく、**TLSに渡されたアプリケーションデータが暗号化の対象**です。たとえば`STARTTLS`の完了後に送るSMTPコマンドやメール本文はTLSに渡されるため、その区間では暗号化されます。TLS 1.3の仕様も、上位のプロトコルがTLS上で動き、TLSがレコードを保護すると説明しています（[RFC 8446、1節・5節](https://www.rfc-editor.org/rfc/rfc8446.html#section-5)、[RFC 3207、4.2節](https://www.rfc-editor.org/rfc/rfc3207.html#section-4.2)）。

### 送信時：暗号化してから外側を包む

以下は説明のため、暗号化済みのTLSレコードが一つのTCPセグメントに収まった例です。実際にはTLSレコードとTCPセグメントが1対1になるとは限りません。TCPはバイト列を分割して運びます（[RFC 9293、2.2節・3.7節](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.7)）。

```text
① アプリが作る         [メール本文などのデータ（平文）]
② TLSが保護する       [TLSの外側ヘッダー][暗号化された本文など]
③ TCPが包む           [TCPヘッダー：送信元・宛先ポート][TLSレコード]
④ IPが包む            [IPヘッダー：送信元・宛先IP][TCPセグメント]
⑤ リンク層が包む      [Ethernetヘッダー：次の機器のMAC等][IPパケット]

実際に流れるフレームの概念図：
┌────────────┬────────────┬────────────┬───────────────┬────────────────┐
│リンク層の      │IPヘッダー   │TCPヘッダー  │TLSレコードの    │TLSレコードの    │
│ヘッダー        │IPアドレス   │ポート番号   │外側ヘッダー     │暗号化された中身│
└────────────┴────────────┴────────────┴───────────────┴────────────────┘
      見える          見える         見える           見える          鍵なしでは読めない
```

TLS 1.3の暗号化されたレコードは、外側に種類・バージョン・長さのフィールドを持ち、その後ろに暗号化された部分を置きます。よって**TLSの暗号化範囲は、IPヘッダー・TCPヘッダーを含まず、TLSレコードの外側ヘッダーも含みません。** IPにはアドレス、TCPにはポート番号が入ることが仕様で定められています（[RFC 8446、5.2節](https://www.rfc-editor.org/rfc/rfc8446.html#section-5.2)、[RFC 9293、3.1節](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.1)）。

| 情報 | 通常のTLS通信中に途中の機器から読めるか | 理由 |
| --- | --- | --- |
| 送信元・宛先IPアドレス | 読める | IPヘッダーはTLSの外側にある |
| TCPの送信元・宛先ポート番号 | 読める | TCPヘッダーはTLSの外側にある |
| TLSレコードの外側の種類・長さなど | 読める | TLSレコードの外側ヘッダーは暗号化されない |
| TLSで保護されたメール本文・添付ファイルの内容 | 読めない | TLSレコードの中で暗号化される |

### 途中のルーターと受信側では何が起こる？

```text
送信側PC                 途中のルーター／ファイアウォール               受信側メールサーバー
アプリの平文                                                          TLSで復号 → アプリの平文
   ↓ TLSで暗号化                                                         ↑
   ↓ TCP → IP → リンク層    →  リンク層を外し、IPを見て転送  →   リンク層 → IP → TCP → TLS
                              必要ならTCPヘッダーも見て通信を制御
                              TLSの中身は復号しない
```

ルーターは受け取ったフレームの**リンク層の包みを外し**、IPアドレスを見て次の宛先を選び、次の区間用のリンク層の包みを付けて送り出します。ここでリンク層の包みを外すことは、**TLSを復号することではありません**。受信側のTLS終端点では、IP・TCPを処理し、TCPのバイト列からTLSレコードを取り出して検証・復号し、アプリケーションに渡します（[RFC 1812、3章・5.2節](https://www.rfc-editor.org/rfc/rfc1812.html)、[RFC 8446、5節](https://www.rfc-editor.org/rfc/rfc8446.html#section-5)）。

**接続開始からすべてのバイトが暗号化されるわけでもありません。** 先にTCP接続を作り、TLSの鍵を決めるための通信を行います。TLS 1.3では初めの`ClientHello`と`ServerHello`は平文で、その後のハンドシェイクメッセージやアプリケーションデータは暗号化されます。メールの`STARTTLS`では、TLS開始前のSMTPのやり取りも平文です（[RFC 8446、1.2節・2節](https://www.rfc-editor.org/rfc/rfc8446.html#section-2)、[RFC 3207、4節](https://www.rfc-editor.org/rfc/rfc3207.html#section-4)）。

なお、Wi-Fiなどのリンク層が独自に暗号化する場合もあります。それは**TLSとは別の保護**です。上の「IPアドレスやポート番号が読める」は、通信を中継・判定する機器が、その区間のリンク層を処理してIPパケットを見たときの話です。TLSだけでIP・TCPヘッダーが暗号化されることはありません（[RFC 1812、3章](https://www.rfc-editor.org/rfc/rfc1812.html)、[RFC 8446、5.2節](https://www.rfc-editor.org/rfc/rfc8446.html#section-5.2)）。

**メールでは、受信側メールサーバーのIPアドレスが見えることと、最終的な受信者のメールアドレスや本文が見えることは別です。** TLSは接続した二者間で終わります。メールサーバーが中継する場合は区間ごとにTLS接続を張り直すため、サーバーは通常、その区間のTLSを復号してメールを処理できます（[RFC 3207、6節](https://www.rfc-editor.org/rfc/rfc3207.html#section-6)）。
