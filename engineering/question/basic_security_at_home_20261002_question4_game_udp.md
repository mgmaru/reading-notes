# 『おうちで学べるセキュリティの基本』2026-10-2 疑問4：ゲームの通信にUDPは使われるか

## 疑問

> ゲームの通信プロトコルはUDPか？
>
> 理由：ゲームは遅延が起こってしまうと成立しないため。

## 回答

**リアルタイムの対戦ゲームでは、UDPを土台にした通信がよく使われます。ただし、ゲームの通信すべてがUDPというわけではありません。** 位置や操作を頻繁に更新するときは「古い情報を待つより、新しい情報を早く使いたい」ことがあります。一方、ログインや購入などにはHTTPSなどが使われます。ゲームの種類と、送る情報の用途で方式を選びます。多少の遅延は避けられませんが、ゲーム側では予測や遅延を補う処理も行います（[Microsoft Learn：ゲームでのTCP・UDP・HTTPの使い分け](https://learn.microsoft.com/en-us/windows/uwp/gaming/work-with-networking-in-your-directx-game)、[Unity：対戦ゲームの通信](https://docs.unity.com/multiplayer/game-types/competitive-games)）。

UDPはデータを運ぶための**トランスポート層のプロトコル**です。実際にどんな位置情報や操作情報をどう表すかは、ゲーム側の通信方式で決めます。

### UDPがリアルタイム通信に向く理由

UDPは、送ったデータの**到着保証・順序保証・自動再送を標準では行いません**。たとえば、ある時点の位置更新が失われても、次の新しい位置更新を待たずに受け取って利用できます。TCPは失われたデータを再送し、アプリには送信順にデータを渡すため、失った部分の回復を待つ間、その後のデータの利用も遅れる場合があります（[RFC 8085：UDPの性質](https://www.rfc-editor.org/rfc/rfc8085.html)、[RFC 9293：TCPの順序保証と再送](https://www.rfc-editor.org/rfc/rfc9293.html)）。

```text
送信側： 位置A ──→ 位置B ──→ 位置C
                  × 損失

UDPを使うゲーム：位置Cが届けば、位置Bを待たずに最新状態を使える設計にできる
TCPの順序保証： 位置Bのデータが回復するまで、後続データの引き渡しを待つ場合がある
```

これは**ゲーム側がそのように設計した場合**の例です。UDPを使うだけで自動的にラグがなくなるわけではありません。通信経路の遅延や損失はUDPでも起きます。また、アプリがUDP上で再送や順序保証を実装すれば、その情報については待ち時間が発生することもあります。UDP自体には混雑を避ける制御もないため、アプリ側で送りすぎないように調整する必要があります（[RFC 8085](https://www.rfc-editor.org/rfc/rfc8085.html)）。

### 送る情報によって扱いを変える

| 情報の例 | 重視すること | 使われる方式の例 |
| --- | --- | --- |
| プレイヤーの位置・照準など、短い間隔で更新される情報 | 古い更新より新しい更新を早く反映する | UDPを土台にした、再送しない通信 |
| アイテム取得・試合結果など、欠けると困る状態変更 | 届いたことを確認し、必要なら再送する | UDP上に信頼性を加えた通信など |
| ログイン・購入など | 要求への応答を確認し、通信内容を保護する | HTTPSなど |

上の例は**設計上の選択肢**で、どのゲームにも共通する固定の決まりではありません。たとえばUnity TransportはUDP上で接続を扱い、必要に応じて信頼性や順序保証を加えられます。Steamのゲーム向け通信APIにも、UDP接続と、信頼性のあるメッセージ・ないメッセージの両方があります（[Unity：UDP上の信頼性と順序保証](https://docs.unity.com/en-us/mps-sdk/integrations)、[Steamworks：ゲーム向け通信API](https://partner.steamgames.com/doc/api/ISteamnetworkingSockets?language=english)）。

**覚え方：** 「ゲームだからUDP」ではなく、**新しさが大切な情報にはUDPを土台にした通信が向き、必ず届けたい情報には届いたことを保証する仕組みを使う**、と考えると整理しやすいです。そもそもの遅延・ばらつき・損失とラグの関係は[疑問3：パケット交換とラグ](./basic_security_at_home_20261002_question3_packet_switching_lag.md)を参照してください。
