# 『おうちで学べるセキュリティの基本』2026-10-2 疑問10：Webサーバーはアクセスをどう数えるか

## 疑問

> Webサーバーは利用者を区別しないとあるが、本当か？ 特定のIPアドレスからの要求回数を数えれば、アクセス数が分かるのではないか？

## 回答

**IPアドレスごとのリクエスト数は数えられます。ただし、それをそのまま「訪問した人の数」や「ページの閲覧回数」とは呼べません。** HTTPは、各リクエストをそれ単独で解釈できるように設計されています。これは「Webサーバーが情報を記録できない」という意味ではありません。たとえば Nginx のアクセスログには、設定に応じて接続元IPアドレス、要求されたリソース、日時、応答コードなどを記録できます（[RFC 9110：HTTPの性質](https://www.rfc-editor.org/rfc/rfc9110.html#section-3.3)、[Nginx：アクセスログの設定](https://nginx.org/en/docs/http/ngx_http_log_module.html)）。

```text
ブラウザ ── GET /index.html ──→ Webサーバー  ← 1リクエスト
         ── GET /style.css  ──→ Webサーバー  ← 1リクエスト
         ── GET /logo.png   ──→ Webサーバー  ← 1リクエスト
```

この例は**1回のページ表示に伴い、サーバーへ3回要求が届いた**場合です。CSSや画像がブラウザのキャッシュなどから読み込まれれば、実際に届く要求数は変わります。したがって、ログの3行を「3ページ閲覧」や「3人」と数えることはできません。

| 数えたいもの | 集計の例 | IPアドレスだけで分かるか |
| --- | --- | --- |
| リクエスト数 | `/index.html` などへの要求を数える | **分かる**。アクセスログに記録された範囲で数えられる |
| ページ閲覧数 | ページ本体への要求や計測イベントを数える | **IPだけでは決まらない**。何を1閲覧とするか定義が必要 |
| 訪問回数（セッション数） | 一連の利用を1回としてまとめる | **正確には分からない**。時間による区切りやセッションIDなどのルールが必要 |
| 利用者数 | 同じ人の複数回の利用をまとめる | **正確には分からない**。ログイン中ならアカウントIDなどを使える |

ページ閲覧とセッションは異なる指標です。たとえば Google Analytics もページ閲覧の累計とセッションを別の指標として定義しています。ただし、その定義をすべてのサイトが採用するわけではありません（[Google Analytics：セッションと閲覧数](https://developers.google.com/analytics/devguides/collection/ga4/sessions)）。

### IPアドレスが「利用者のID」にならない理由

- 家庭内や会社内の**複数人が、同じ外向きIPアドレス**を使うことがあります。
- 同じ人でも、回線や接続先ネットワークが変わると**異なるIPアドレス**からアクセスすることがあります。
- CDNやリバースプロキシを経由する構成では、Webサーバーが直接見る接続元は**その中継機器のIPアドレス**である場合があります。元の接続元IPを取り扱う場合も、中継機器の設定を確認する必要があります（[Apache HTTP Server：プロキシ経由の接続元IP](https://httpd.apache.org/docs/2.4/mod/mod_remoteip.html)）。
- リクエストの送信元には、**人が操作するブラウザ以外にクローラーなど**も含まれます（[RFC 9110：User Agent](https://www.rfc-editor.org/rfc/rfc9110.html#section-3.5)）。

たとえば、同じ家の2人が1回ずつ閲覧すると、IP単位では「1つのIPから2回」です。逆に、1人が自宅と携帯回線から1回ずつ閲覧すると「2つのIPから各1回」です。**IP別の要求回数は分かっても、そこから実人数は確定しません。**

利用をまたいで同じブラウザやログイン中のアカウントを見分ける方法は、[疑問11・12：Cookieとセッション](./basic_security_at_home_20261002_question11_12_cookie_session.md)で説明します。
