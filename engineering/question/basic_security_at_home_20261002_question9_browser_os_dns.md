# 『おうちで学べるセキュリティの基本』2026-10-2 疑問9：ブラウザとOSはどちらがDNSへ問い合わせるか

## 疑問

> ブラウザでURLを入力した後に、DNSへIPアドレスを問い合わせるのはOSの役割か？

## 回答

**一般的には、ブラウザが名前解決を必要と判断し、OSの名前解決機能を利用します。** OS側のリゾルバーは、設定された再帰リゾルバーへ問い合わせます。ただし、ブラウザがDNS over HTTPS（DoH）などを使って、独自に再帰リゾルバーへ問い合わせる設定もあります。したがって「常にOSだけがDNSへ問い合わせる」とは言えません（[RFC 9499：スタブリゾルバーと再帰リゾルバー](https://www.rfc-editor.org/rfc/rfc9499.html)、[Firefoxヘルプ：DNS over HTTPS](https://support.mozilla.org/en-US/kb/firefox-dns-over-https)）。

### 典型的な流れ

`https://www.example.com/help/` を開く場合の概略です。

```text
ブラウザ：URLからホスト名 www.example.com を取り出す
    ↓  名前解決を依頼
OSの名前解決機能（スタブリゾルバー）
    ↓  必要なら設定済みの再帰リゾルバーへ問い合わせる
再帰リゾルバー：必要なら権威DNSサーバーをたどる
    ↓  IPアドレスを回答
OS → ブラウザ：結果を渡す
    ↓
ブラウザ：得たIPアドレスを使って接続を開始する
```

| 担当 | 主な仕事 |
| --- | --- |
| ブラウザ | URLを解釈し、接続先のホスト名について名前解決を始める |
| OSの名前解決機能 | ブラウザなどからの依頼を受け、ローカル設定や指定されたDNSを利用する |
| 再帰リゾルバー | キャッシュを確認し、必要なら権威サーバーをたどって結果を返す |
| 権威DNSサーバー | 自分が管理するゾーンのレコードや委任先を答える |

DNSで調べるのは主に**ホスト名**の部分です。`/help/` はWebサーバー上で要求するパスなので、DNSの問い合わせには含めません。また、ブラウザ・OS・再帰リゾルバーなどに答えがキャッシュされていれば、権威サーバーまで問い合わせずに済む場合があります（[RFC 1034：リゾルバーとキャッシュ](https://www.rfc-editor.org/rfc/rfc1034.html)、[RFC 9499：DNSの役割](https://www.rfc-editor.org/rfc/rfc9499.html)）。

### 例外：ブラウザがDoHを使う場合

ブラウザがDoHを使う設定なら、ブラウザ自身がHTTPS経由でDNSの問い合わせを送ることがあります。この場合、OSに設定された通常のDNSリゾルバーを使わないことがあります。ただし、通信を実際に送受信するためのOSのネットワーク機能は使います。利用する経路や、DoHが失敗したときの動作はブラウザと設定によって変わります（[Firefoxヘルプ：DoHの動作とOS設定への切り替え](https://support.mozilla.org/en-US/kb/firefox-dns-over-https)）。

再帰リゾルバーが権威サーバーをどうたどるかは、[疑問6〜8：DNSの階層と委任](./basic_security_at_home_20261002_question6_7_8_dns_hierarchy.md)を参照してください。
