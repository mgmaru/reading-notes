# 『おうちで学べるセキュリティの基本』2026-10-2 疑問11・12と追加疑問：Cookieとセッション

## 疑問

11. Webサーバーは利用者のIPアドレスではなく、セッションIDで識別しているという認識でよいか？
12. Cookieの期限が切れた後に再度アクセスすると、アクセス回数はカウントされるか？

## 回答：疑問11

**セッションを使うWebアプリでは、セッションIDで一連のリクエストを結びつける、という理解でおおむね合っています。** ただし、IPアドレスが見えなくなるわけではありません。サーバーは接続元IPを記録でき、アプリはログイン中のアカウントIDなども扱えます。何を識別するかは目的によって異なります（[Nginx：アクセスログ](https://nginx.org/en/docs/http/ngx_http_log_module.html)、[OWASP：セッション管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)）。

```text
最初の要求    ブラウザ ── sid なし ────────────→ Webアプリ
             ブラウザ ← Set-Cookie: sid=ABC ─ Webアプリ

次の要求      ブラウザ ── Cookie: sid=ABC ────→ Webアプリ
                                        sid=ABC に対応するセッションを探す
```

`ABC` は仕組みを示す仮の値です。実際の認証用セッションIDには、推測しにくい値を使います。`Set-Cookie` はサーバーからブラウザへCookieを保存させ、次の要求でブラウザが該当するCookieを `Cookie` ヘッダーに載せて返します。Webアプリは受け取ったIDを、サーバー側のセッション情報と照合できます（[RFC 6265：Cookieの送受信](https://www.rfc-editor.org/rfc/rfc6265.html#section-3)、[OWASP：セッションIDの性質](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#session-id-properties)）。

| 情報 | 分かること | 注意点 |
| --- | --- | --- |
| 接続元IPアドレス | その要求がどのIPから届いたか | 同じIPを複数人で共有したり、同じ人のIPが変わったりする |
| セッションID | 同じセッションに属する要求か | **同一人物の証明ではない**。1人が複数セッションを持つこともある |
| ログイン中のアカウントID | どのアカウントで認証されているか | 同じアカウントを複数の端末から使うこともある |

**Cookie自体が必ずセッションIDとは限りません。** 言語設定や分析用の識別子など、別の値も保存できます。また、ログインしていない利用者にもセッションを作れます（[RFC 6265：Cookieの用途](https://www.rfc-editor.org/rfc/rfc6265.html#section-2)、[OWASP：匿名ユーザーのセッション](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#introduction)）。

## 追加疑問：最初のページ表示中、どのリクエストにセッションIDが付くか？

> 1ページの表示には複数のリクエストが発生する。サーバーがセッションIDを送っても、ブラウザがまだ保存していない間に送ったリクエストにはIDが付かないのか？

**はい。ブラウザがセッションIDを入れたCookieを受け取り、保存してから作るリクエストに、そのIDを付けられます。** 保存前に送信済みのリクエストへ、後からIDが追加されることはありません。「保存」はブラウザがCookieを利用できる状態にすることであり、必ずしもディスクへ書き込むことを意味しません（[RFC 6265：Cookieの保存と送信](https://www.rfc-editor.org/rfc/rfc6265.html#section-4.1.2)、[MDN：Cookieの仕組み](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies)）。

次は、同じサイトへのリクエストが並行して起きる場合の**説明用の例**です。`ABC` は仮のセッションIDです。

```text
時刻  ブラウザ（クライアント）                  Webアプリ（サーバー）
 ①   GET /page        ── sid なし ──────────→  セッションを作成
 ②   GET /api/data    ── sid なし ──────────→  ①の応答を処理する前に送信
 ③                    ←── Set-Cookie: sid=ABC  ①への応答
 ④   Cookieを保存：sid=ABC
 ⑤   GET /style.css   ── Cookie: sid=ABC ──→  保存後に送信
```

| リクエストを作る時点 | `sid=ABC` は付くか | 理由 |
| --- | --- | --- |
| ③の応答をブラウザが処理する前 | **付かない** | ブラウザにまだそのCookieがない |
| ④で保存した後 | **条件が合えば付く** | 保存済みのCookieを `Cookie` ヘッダーで送る |
| 保存前に送信済み | **後からは付かない** | 送信済みのリクエストは書き換わらない |

したがって、**最初のページ表示に関わるリクエストでも、開始したタイミングによってIDの有無が異なります。** たとえば、HTMLの応答に含まれる `Set-Cookie` を保存した後にCSSや画像を要求するなら、それらのリクエストにもIDが付きます。保存後は、HTML・CSS・画像・APIなどの種類に関係なく、Cookieの送信先と一致するリクエストに同じIDを繰り返し送ります（サーバーがIDを更新するまで）。[RFC 6265：Cookieヘッダー](https://www.rfc-editor.org/rfc/rfc6265.html#section-5.4)

ただし、保存後でも常に付くわけではありません。

- Cookieの `Domain`・`Path`・`Secure`・`SameSite` などの条件に合わない宛先には送られません。たとえば、無関係な別ドメインにある画像には、そのサイトのCookieは通常送られません（[MDN：Cookieを送る範囲](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies#define_where_cookies_are_sent)）。
- ブラウザのキャッシュから読み込む場合は、サーバーへのリクエスト自体が発生しないことがあります。
- Cookieが送られても、サーバーがCSSや画像の処理でセッションIDを**使うとは限りません**。Cookieを付けるかどうかと、サーバーがその値を利用するかどうかは別です。

## 回答：疑問12

**Cookieの期限が切れても、新しい要求がサーバーに届けば、その要求を数えることはできます。** ただし、以前の利用と同じ人・同じセッションとして数えるかは、集計方法と残っている識別情報で変わります。Cookieの `Max-Age` や `Expires` で定めた期限が過ぎると、ブラウザはそのCookieを次の要求に付けません（[RFC 6265：有効期限と送信](https://www.rfc-editor.org/rfc/rfc6265.html#section-4.1.2)）。

次は「1回目にページを見た後、**セッションIDを入れたCookieだけ**が期限切れになり、同じページをもう一度見た」例です。

| 集計方法 | 2回目のアクセスの扱い |
| --- | --- |
| サーバーが受け取った要求数 | **追加で数える**。その要求が届いたこと自体は変わらない |
| ページ閲覧数 | ページ表示を計測する仕組みが再び記録すれば、**追加で数える**。集計方法によって結果は変わる |
| セッションID単位の回数 | 以前のIDは届かない。新しいセッションを発行すれば、**新しいセッションとして**数える。以前のセッション内の回数はそのまま引き継がない |
| ログイン中のアカウント単位の回数 | 別の有効な認証情報で同じアカウントだと分かれば、**同じアカウントの累計に**加えられる |
| セッションIDだけを使った「初めての利用者」判定 | 以前のIDが届かないため、**新規と誤判定する可能性**がある |

たとえば、最初のセッションでページを1回見て、そのセッションIDのCookieが期限切れになった後に再訪したとします。2回目の要求がサーバーに届けば、**サーバーへの要求は累計2回**です。新しいセッションを作る設計なら、**セッションAで1回、セッションBで1回**となります。

Cookieの期限と、**サーバー側で管理するセッションの期限は別**です。Cookieが残っていてもサーバー側のセッションが失効していれば、そのIDで元のセッションを継続できません。逆にCookieだけが期限切れで送られなければ、サーバー側に元の記録が残っていても、その要求を元のセッションへ結びつける材料がありません（[OWASP：セッションの失効](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#session-expiration)）。

**「アクセス回数がカウントされるか」は、何を1回と数えるかを先に決めると答えられます。** IPアドレスとアクセスログによる集計の違いは[疑問10：Webサーバーのアクセス数](./basic_security_at_home_20261002_question10_http_access.md)で整理しています。
