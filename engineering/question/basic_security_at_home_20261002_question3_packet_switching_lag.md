# 『おうちで学べるセキュリティの基本』2026-10-2 疑問3：パケット交換と「ラグ」

## 疑問

> パケット交換について、届くまでの時間が長くなったり届く前に失われたりとあるが、これが「ラグ」という現象か？

## 回答

**はい、通信の遅延やパケットの損失は、ゲームなどで感じる「ラグ」の原因になります。** ただし「ラグ」は利用者が感じる反応の遅さや動きの不自然さを表す日常的な言葉です。通信が混み合ったときの**遅延**と**損失**は別の現象であり、どちらもラグにつながり得ます。ゲームサーバーの処理遅れや、自分の端末で画面を描く処理の遅れでも、似た症状が出ます（[RFC 7679：片方向遅延](https://www.rfc-editor.org/rfc/rfc7679.html)、[RFC 7680：片方向パケット損失](https://www.rfc-editor.org/rfc/rfc7680.html)、[Microsoft Learn：ゲームの通信品質](https://learn.microsoft.com/en-us/gaming/gdk/docs/services/multiplayer/concepts/live-multiplayer-concepts)）。

### 混雑すると何が起きるか

パケット交換では、複数の通信が同じ回線や通信機器を共有します。ルーターなどにパケットが一度に集まると、処理されるまで待ち行列に並びます。行列が長くなると到着が遅れ、保持できる量を超えたパケットは捨てられることがあります。**パケット交換なら必ず遅延・損失が起きる**という意味ではありません。混雑以外にも、無線の電波状況などで損失は起こり得ます（[RFC 7567：待ち行列とパケットの破棄](https://www.rfc-editor.org/rfc/rfc7567.html)）。

```text
自分のPC ──→ [ルーターの待ち行列] ──→ ゲームサーバー
                 ↑
            ほかの人の通信も流入

行列に並ぶ時間が増える → パケットが遅れて届く
行列があふれる       → 一部のパケットが捨てられる
```

| 現象 | 何が起きるか | ゲームで見える例 |
| --- | --- | --- |
| 遅延（レイテンシー） | 操作などの情報が相手に届くまで時間がかかる | ボタンを押した後、相手側で動きが反映されるまで間が空く |
| 遅延のばらつき（ジッター） | 届く時間が毎回まちまちになる | 相手の動きが滑らかにならず、ときどき引っかかる |
| パケット損失（ロス） | 送った情報の一部が届かない | 位置更新が抜けて動きが飛ぶ。再送する仕組みを使っていれば、その完了待ちで反映が遅れることもある |

遅延・ばらつき・損失はそれぞれ測定できる別の指標です。測定では、遅れて届いたパケットと、決めた待ち時間内に届かなかったパケットを分けて扱います（[RFC 7679](https://www.rfc-editor.org/rfc/rfc7679.html)、[RFC 3393：遅延のばらつき](https://www.rfc-editor.org/rfc/rfc3393.html)、[RFC 7680](https://www.rfc-editor.org/rfc/rfc7680.html)）。

### 「失われたら必ずラグになる」わけではない

たとえば、ゲームが位置情報を何度も送る場合、古い位置情報が1回届かなくても、次の新しい情報で画面を更新できます。その間の動きを推測して滑らかに見せる実装もあります。一方、「アイテムを取得した」のように欠けると困る情報は、届いたことを確認し、必要なら送り直す必要があります。**損失を画面上でどう感じるかは、送った内容とゲーム側の処理によって変わります。** 詳しくは[疑問4：ゲームとUDP](./basic_security_at_home_20261002_question4_game_udp.md)で説明します（[Unity：対戦ゲームの通信](https://docs.unity.com/multiplayer/game-types/competitive-games)、[RFC 9293：TCPの再送](https://www.rfc-editor.org/rfc/rfc9293.html)）。

ゲームの「ping」は通常、相手まで行って戻る**往復時間（RTT）**の目安です。pingの平均が低くても、急な遅延の増加やパケット損失があれば、プレイ中に引っかかる場合があります。原因を切り分けるなら、pingに加えて損失率、ゲーム内のフレームレート、サーバーの状態を確認します（[Microsoft Learn：ゲームの通信品質の測定](https://learn.microsoft.com/en-us/gaming/gdk/docs/features/console/networking/game-mesh/qos-networking)）。
